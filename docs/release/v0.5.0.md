# quic-net v0.5.0 - A working connection

**A QUIC client and server, handshaking through tls-net and carrying streams.** Sans-IO: the caller owns the socket and the clock, passes datagrams in, and sends what comes out.

```rust
use quic_net::{Config, Connection, Event};

let mut conn = Connection::client(&tls, "example.com", Config::default(), my_cid, random_dcid, now)?;
loop {
    while conn.poll_transmit(now, &mut out) { socket.send(&out)?; }
    // ... wait for a datagram or conn.poll_timeout() ...
    conn.handle_datagram(now, &mut datagram);
    while let Some(event) = conn.poll_event() {
        if let Event::Connected = event {
            let id = conn.open_stream(true).unwrap();
            conn.stream_write(id, b"hello")?;
        }
    }
}
```

## What is quic-net?

QUIC (RFC 9000) for Rust, built up from its parts. The wire layer (0.2), packet protection (0.3), streams (0.4), and address validation now run as one connection.

## What's in 0.5.0

- **`Connection`**, client and server. The handshake runs through tls-net 0.11's QUIC interface, which wraps rustls, with Initial, Handshake, and 1-RTT packet number spaces, coalesced packets, and the padding rules for Initials.
- **Recovery for the handshake and streams**: ACKs, loss detection by packet and time thresholds, and the probe timeout with backoff (RFC 9002). Congestion control comes in 0.6.
- **Retry and version negotiation** on the client; **the amplification limit** on the server, with address validation tokens from 0.5's `Tokens`.
- **Keys** discarded at the right moments, and the peer's key updates followed.
- **Streams** with flow control both ways; closing with `CONNECTION_CLOSE`; the idle timeout.

## Found by the new fuzz target

- On a resumed TLS session, rustls offers the previous session's transport parameters before the handshake. The client now waits for the server's new ones.
- After a lost server flight, a client could probe every PTO without backing off. It now keeps its backoff across Initial ACKs and stops probing once the server has acknowledged a Handshake packet, as RFC 9002 says.

## Tested

A handshake; a 100 KB stream echo; the echo over channels that lose every third, fifth, or seventh datagram; three connections on one client, the later ones resuming; Retry with address validation tokens; closing; the server within three times what it received. A `connection` fuzz target drops, duplicates, and changes datagrams of real handshakes.

## Known gaps

- No congestion control or pacing yet: a sender is limited only by flow control.
- No 0-RTT, migration, extra connection IDs, or key updates started by this endpoint.

## What's next

`0.6.0`: congestion control and pacing, migration and path validation, more connection IDs, and key updates.
