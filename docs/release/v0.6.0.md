# quic-net v0.6.0 - Congestion control

**NewReno with pacing.** A connection now keeps what it has in flight within a congestion window that grows with acknowledgements and halves on loss, and spreads each window over the round trip.

```rust
let mut conn = quic_net::Connection::client(&tls, "example.com", Config::default(), my_cid, random_dcid, now)?;
// ... after some traffic:
println!("window {} bytes, {} in flight, {:?}", conn.congestion_window(), conn.bytes_in_flight(), conn.congestion_state());
```

## What is quic-net?

QUIC (RFC 9000) for Rust, sans-IO: the caller owns the socket and the clock. 0.5 made it a working connection; this release makes it safe to run on a shared path.

## What's in 0.6.0

- **NewReno** (RFC 9002 section 7): slow start, one halving per recovery period, congestion avoidance, the minimum window, and persistent congestion.
- **Bytes in flight** across every packet number space; ACKs are never held back, and probes and closes may pass the window.
- **Pacing** at 1.25 times the window per round trip, in bursts of up to ten datagrams; `poll_timeout` includes the pacing timer. `Config::pacing` turns it off.
- `congestion_window()`, `bytes_in_flight()`, and `congestion_state()` on the connection.

## Tested

A 400 KB transfer through a bottleneck that drops what its queue cannot hold: the window bounds what is in flight, shrinks after loss, and every byte arrives. Unit tests follow the RFC's window rules step by step.

## Fixed while building it

A pacing timer could be set to the exact current moment and never advance, so a caller woken by `poll_timeout` would spin without sending. The pacer now accepts a budget within a byte of a datagram, and a timer that has fired is cleared.

## Known gaps

- No migration, extra connection IDs, key updates started by this endpoint, or 0-RTT yet (0.7).

## What's next
